# SLT Support Chatbot — RAG with Ollama

A clinically-aligned **Retrieval-Augmented Generation (RAG)** chatbot built to support Speech and Language Therapy (SLT) home practice. Therapists select a patient profile; parents receive evidence-based, patient-specific coaching generated by a locally-running LLM grounded in an NHS-style clinical document knowledge base.

---

## Project Overview

The system retrieves therapist-approved clinical resources from a ChromaDB vector store and injects them — alongside the patient's live profile — into a structured prompt. The LLM never invents clinical advice; every response is anchored to retrieved evidence and patient-specific context.

### Key Features

| Feature | Detail |
|---|---|
| **Local LLM** | Ollama-hosted model (configurable via `.env`) |
| **Vector store** | ChromaDB with rich per-document metadata |
| **Embedding model** | `mxbai-embed-large` via Ollama |
| **UI** | Streamlit with sidebar patient/parent profile |
| **Evaluation** | LLM-as-Judge across 4 clinical dimensions |

---

## Architecture

```
medbase/ (PDF clinical documents)
    │
    ▼
chunking_embedding_ingestion.py
    │   RecursiveCharacterTextSplitter (chunk_size=250, overlap=50)
    │   Rich metadata enrichment (therapy_focus, age_range, target_skills)
    ▼
chroma_db/ (persisted ChromaDB vector store)
    │
    ▼
ct-latest.py  ←  patients.json
    │   RAG Optimisation 1: Metadata filtering (therapy_focus $in filter)
    │   RAG Optimisation 2: Multi-Query Retrieval (MultiQueryRetriever)
    │   RAG Optimisation 3: Evidence-question detection (disables focus filter)
    │   RAG Optimisation 4: Minimal-pairs CSV lookup (phoneme_minimal_pairs.csv)
    ▼
Streamlit Chat UI (patient sidebar + streaming response)
```

---

## RAG Optimisations

1. **Metadata Filtering** — Each document is tagged with `therapy_focus` (phonology, articulation, stammering, early_language). Queries are routed to the clinically relevant subset of the knowledge base using a ChromaDB `$in` filter derived from the patient's diagnosis/primary concern.

2. **Multi-Query Retrieval** — `MultiQueryRetriever` rephrases the therapist's question several ways and merges deduplicated results, improving recall when natural language doesn't match PDF vocabulary.

3. **Evidence-Question Detection** — Questions containing keywords like *"why"*, *"research"*, *"evidence"* bypass the therapy_focus filter so academic papers in the medbase are always included in the retrieval pool.

4. **Minimal-Pairs CSV Lookup** — When minimal pair practice is requested (or a substitution error is described), real word pairs are fetched deterministically from `phoneme_minimal_pairs.csv` and injected into the prompt before vector-store results, preventing LLM hallucination of phoneme contrasts.

## Knowledge Base (`medbase/`)

The vector store is built from two categories of documents:

**Clinical Practice Handouts**
- Minimal Pairs, Syllable Clapping, Identifying Sounds, Speech Discrimination Games
- Typical Speech Sound Development, Strategies for Speech Sound Difficulties
- Intensive Interaction, Language Top Tips, Early Language Development Advice
- Compound Words, Where in the Word, Transition & Changes

**Research Papers**
- McLeod & Crowe (2018) — Consonant Acquisition in 27 Languages
- Sugden et al. (2019, 2020) — Parent Home Practice & Multiple Oppositions Intervention
- Pritchard (2024) — SLT–Parent Collaboration Scoping Review
- Hegarty et al. (2021) — Intervention Intensity (Qualitative)
- McFaul et al. (2022) — Intensity for Severe SSD (QI Project)
- Leafe et al. (2024) — Home Practice Intensity (Realist Review)
- Harding et al. (2024) — Outcome Measures Umbrella Review
- Kim et al. (2025) — LLMs in Speech-Language Pathology

## Evaluation Framework

Four independent evaluation scripts use an **LLM-as-Judge** methodology (same model, `temperature=0`) to compare:

- **Condition A** — Full RAG system (patient context + ChromaDB retrieval + LLM)
- **Condition C** — Baseline LLM (raw question only, no context, no retrieval)

| Script | Dimension | Metrics |
|---|---|---|
| `eval_contextual_accuracy.py` | Contextual Accuracy | stage_accuracy, accuracy_rule, patient_specificity, clinical_safety, overall_car |
| `eval_explainability.py` | Explainability | clarity, reasoning_transparency, jargon_avoidance, actionability |
| `eval_trustworthiness.py` | Trustworthiness | evidence_grounding, hallucination_risk, clinical_safety |
| `eval_usability.py` | Usability | response_length, structure, parent_friendliness |

Results are saved as CSV files for research paper analysis.

## Prerequisites

- Python 3.11+
- [Ollama](https://ollama.com) installed and running locally
- Required Ollama models pulled:
  ```
  ollama pull mxbai-embed-large
  ollama pull <your chat model>   # e.g. qwen3, llama3.2, mistral
  ```

## Installation

### 1. Clone the repository

```bash
git clone <your-repo-url>
cd RAG-with-Ollama-slt
```

### 2. Create and activate a virtual environment

```bash
python -m venv venv
source venv/bin/activate        # macOS / Linux
# venv\Scripts\Activate         # Windows
```

### 3. Install dependencies

```bash
pip install -r requirements.txt
```

### 4. Configure environment variables

Copy or rename `.env.example` to `.env` and fill in your values:

```env
EMBEDDING_MODEL=mxbai-embed-large
CHAT_MODEL=qwen3                   # or llama3.2, mistral, etc.
MODEL_PROVIDER=ollama
COLLECTION_NAME=slt_documents
DATABASE_LOCATION=./chroma_db
DATASET_STORAGE_FOLDER=./
```

---

## Running the System

### Step 1 — Ingest documents into ChromaDB

Run this once (or whenever `medbase/` changes). It **deletes and rebuilds** the vector store.

```bash
python chunking_embedding_ingestion.py
```

### Step 2 — Launch the Streamlit chatbot

```bash
streamlit run ct-latest.py
```

Open [http://localhost:8501](http://localhost:8501) in your browser. Select a patient from the sidebar and start chatting.

---

## Running Evaluations

Each evaluation script runs independently and outputs a CSV:

```bash
python eval_contextual_accuracy.py
python eval_explainability.py
python eval_trustworthiness.py
python eval_usability.py
```
